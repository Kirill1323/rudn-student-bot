# RUDN Student Bot — пилот (этап 2)

Python 3.11+, aiogram 3, SQLite. Работает через Telegram long polling; нужен интернет и токен BotFather.

## Запуск

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# Скопировать .env.example в .env и указать BOT_TOKEN, ADMIN_IDS
python bot.py
```

Узнать свой Telegram ID можно через `/myid` (после первого запуска); затем вписать его в ADMIN_IDS и перезапустить. Не публикуйте `.env`, `bot.db` и токен.

## Сценарий

1. Студент: `/start`, `/group ЭЭКбд-04-26`, `/today`, `/week`, `/hw`.
2. Староста: `/apply` (подаёт заявку, **не** получает права автоматически).
3. Администратор: `/pending`, проверяет личность и статус старосты **вне бота**, затем `/approve 1` либо `/reject 1`. Также доступны `/grant TG_ID ГРУППА` и `/revoke TG_ID ГРУППА`.
4. Староста: `/addhw Математика | 2026-12-01 | Решить №5`; `/edithw 1 | Математика | 2026-12-02 | Решить №6`; `/delhw 1`.
5. Староста: `/addlesson 2026-12-01 | 09:00 | Математика | 101`; `/dellesson 1`.

ID домашних заданий и пар отображаются в `/hw` и `/week` (для текущих и будущих записей). Все операции редактирования проверяют права и принадлежность записи к группе на сервере.

## Ограничения пилота

- Расписание вводится вручную, автоматической синхронизации с РУДН пока нет.
- Группы вводятся текстом; нет проверки по официальному справочнику.
- Подтверждение старосты выполняется администратором вручную; бот не доказывает статус заявителя.
- Уведомления, прикрепление файлов, изменение существующих пар, полноценная история изменений, резервное копирование и панель администратора — следующие этапы.
- Время занятий вводится как московское локальное время; часовой пояс исходного API ещё не подтверждён.
- SQLite подходит для ограниченного пилота, не для масштабного промышленного развёртывания.
